RAG pricer & the ensemble

Three flawed models, combined, beat every one alone.

Why this matters for the switch: ensembling is a quietly powerful production trick — combine diverse models and the errors cancel. Knowing why it works (uncorrelated errors) and building one is exactly the kind of practical ML judgment teams pay for.

Today's win

You can build a RAG-based frontier pricer (vector-search for similar products → GPT context) and combine three different pricers into an ensemble that beats them all.

The three pricers, then a blend

You now have three ways to price a product: the specialist (fine-tuned Llama on Modal), the frontier RAG pricer (GPT-5.1 fed similar items found by vector search), and the neural network from Week 6. Each errs differently — so you ensemble them.

Key concepts

  • RAG without LangChain. Raw chromadb + an encoder: embed 800K product descriptions (all-MiniLM-L6-v2, 384 dims) once, then query for the k nearest at price time.
  • The frontier RAG pricer. For a new item, retrieve 5 similar items with known prices, put them in the prompt as context, and ask GPT-5.1 to estimate — grounding the guess in real comps.
  • RAG beat fine-tuning this time. Frontier-RAG hit $30.19 MAE vs the fine-tuned specialist's $39.85 — an inference-time technique beating an expensive training one.
  • Ensembles cancel error. If model A overshoots by $10 and B undershoots by $10, the blend is right. Gains are biggest when the models are diverse (different methods err differently).
  • The blend. A weighted combination (≈80% RAG + 10% specialist + 10% NN) → $29.90 MAE, R² ≈ 87% — better than any single model.
  • Productionize the code. Move from notebooks to modules with type hints, docstrings, and logging; each pricer becomes a reusable agent.

The code shape to memorize

# RAG pricer: find comps, then ask the frontier model
def find_similars(item):
    vec = encoder.encode(item.summary)
    res = collection.query(query_embeddings=[vec.tolist()], n_results=5)
    return res["documents"][0], [m["price"] for m in res["metadatas"][0]]

def gpt_rag(item):
    docs, prices = find_similars(item)
    msg = f"Estimate the price.\n{item.summary}\nSimilar items:\n" + \
          "\n".join(f"- {d} -> ${p}" for d, p in zip(docs, prices))
    return parse_price(completion(model="gpt-5.1", messages=[{"role":"user","content":msg}]))

# ensemble: blend three diverse pricers
def ensemble(item):
    return gpt_rag(item)*0.8 + specialist(item)*0.1 + neural_net(item)*0.1
Interview-ready framing: "Why does an ensemble of weaker models win?" — Only if their errors are uncorrelated. Three models using the same method err the same way (no gain); a fine-tune, a RAG frontier, and a neural net err differently, so blending cancels noise.
