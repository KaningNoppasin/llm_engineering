LLM Engineering ● Week 8 ● Day 3 Recap

Structured outputs & the deal scanner

Force the model to return a typed object — guaranteed, not hoped-for.

Why this matters for the switch: real systems need reliable data out of LLMs, not prose you regex. Structured outputs are how production agents pass data between steps safely — a pattern you'll use in almost every serious LLM app.

Today's win

You can force an LLM to return a validated Pydantic object via constrained decoding, and build a deal-scanner agent that extracts structured deals from messy RSS feeds.

The big upgrade over Week 5's JSON

Week 5 used response_format={"type":"json_object"} — valid JSON, but any shape. Structured outputs go further: you give a Pydantic schema and constrained decoding guarantees the reply matches it — the client even hands you back a typed Python object.

Key concepts

  • Define the shape as a Pydantic BaseModel. Class attributes (with Field descriptions) become a JSON schema the model must fill.
  • Constrained decoding is the magic. At each step, the provider zeroes out token probabilities that would break the schema — so the model can only emit valid JSON.
  • You get an object, not a string. ...parse(response_format=DealSelection) returns message.parsed as a DealSelection instance — no parsing code.
  • The deal scanner. Pull RSS deal feeds (Feedparser), pass the noisy text to the model, and extract clean Deals: product_description, price, url.
  • LLMs beat regex at messy parsing. "$100 off $500" → the model correctly returns price=400; brittle parsers can't reason about that.
  • Notify via Pushover. A messaging agent crafts a hype message and POSTs it to Pushover to ping your phone about a good deal.

The code shape to memorize

from pydantic import BaseModel

class Deal(BaseModel):
    product_description: str
    price: float          # actual price ("$100 off $500" -> 400)
    url: str

class DealSelection(BaseModel):
    deals: list[Deal]

# constrained decoding: the reply MUST match the schema
resp = openai.chat.completions.parse(
    model="gpt-5-mini",
    messages=[{"role": "system", "content": SYS}, {"role": "user", "content": feed_text}],
    response_format=DealSelection)
for deal in resp.choices[0].message.parsed.deals:   # typed objects!
    print(deal.price, deal.url)
Interview-ready framing: "json_object vs structured outputs?" — json_object only promises valid JSON (any keys); structured outputs use constrained decoding to guarantee your exact schema, and deserialize to a typed object. Use the latter whenever shape matters.
