LLM Engineering ● Week 8 ● Day 4 Recap

Multi-agent orchestration

A planning agent that uses other agents as tools, autonomously.

Why this matters for the switch: "agents" is the hottest word in AI hiring right now. Building a real multi-agent system — a planner that orchestrates specialized agents via tool calling, with memory — is the single most marketable thing in this course.

Today's win

You can build a planning agent that treats other agents as tools and runs the while not done agent loop until the goal is met.

The architecture

A Planning Agent coordinates three specialists as tools: the ScannerAgent (finds deals via structured outputs), the EnsembleAgent (prices them with the three pricers), and the MessagingAgent (notifies you). The DealAgentFramework wires them together with logging and persistent memory.

Key concepts

  • Agents as tools. Each specialist's method (scan, estimate, notify) is exposed as a tool JSON definition the planner can call (Week 2's tool calling, scaled up).
  • The agent loop is what makes it "agentic." while not done: — call the model with tools; if finish_reason == "tool_calls", run the tool and loop; else stop.
  • Specialized agents collaborate. Scanner → Ensemble pricer → Messenger, each doing one job well — the division-of-labor pattern of real agent systems.
  • The framework orchestrates. DealAgentFramework owns the Chroma store, the agents, colored per-agent logging, and the run cycle.
  • Memory gives autonomy. Found Opportunity objects persist to memory.json and are fed back into prompts so the agent doesn't re-surface old deals.
  • It's genuinely multi-model. One cycle makes ~34 model calls across frontier (GPT-5, GPT-5.1, Claude 4.5) and open-source models — ~30 deals scanned, 5 priced, best one notified.

The code shape to memorize

# tools = the other agents, described as JSON
tools = [{"type": "function", "function": scan_fn},
         {"type": "function", "function": estimate_fn},
         {"type": "function", "function": notify_fn}]

# the agent loop
done = False
while not done:
    response = openai.chat.completions.create(model=MODEL, messages=messages, tools=tools)
    if response.choices[0].finish_reason == "tool_calls":
        msg = response.choices[0].message
        messages.append(msg)
        messages.extend(handle_tool_call(msg))   # dispatch to the right agent
    else:
        done = True
Interview-ready framing: "What makes a system 'agentic' and not just a script?" — The loop with autonomy: the LLM decides which tool to call next and when it's finished, rather than you hard-coding the sequence. Tools + loop + memory = an agent.
