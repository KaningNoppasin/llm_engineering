Week 4 glossary

Model selection & evaluation: benchmarks, leaderboards, code-gen, metrics. Print & pin.

New terms from Week 4. See also the Week 1, Week 2, and Week 3 glossaries.

TermMeaningDay
Model selection (2-phase)Filter by basics (cost/context/speed/license), then compare benchmarks, then validate on your task.1
Chinchilla scaling lawCompute-optimal training pairs params with data (~20 tokens/param); doubling params wants ~2× data.1
GPQA448 PhD-level science Q&A; PhDs ~65%, non-PhD+Google ~34%.1
MMLU-ProHarder successor to MMLU: 10 options, de-ambiguated, contamination-aware.1
HLEHumanity's Last Exam — ~2,500 superhuman-hard questions; models ~2–3% at release.1
LiveCodeBenchCoding benchmark with rotating problems to resist contamination.1
Data contaminationBenchmark questions leaking into training data, inflating scores via memorization.1
Overfitting (to a benchmark)Repeatedly picking models by one metric, optimizing the metric not real capability.1
Artificial AnalysisLeaderboard plotting composite intelligence vs cost & speed; aim for cheap & smart.2
VellumOne-stop table of API cost, context window, and speed across providers.2
SEALSpecialized expert benchmarks (tool use, languages, vision, security).2
LiveBenchContamination-resistant leaderboard that refreshes its questions.2
LM ArenaBlind head-to-head human votes → Elo ratings; crowd judgment, hard to game.2
Elo ratingRelative skill score from pairwise wins/losses (here, from human preference votes).2
Automation / Augmentation / AgenticThe three commercial patterns by rising autonomy: replace work → co-pilot → autonomous decisions.2
Code translation promptSystem prompt ("convert to high-performance C++, code only") + user prompt with source & compile info.3
Native compilationCompiling to machine code (clang++ -Ofast -mcpu=native) — the main reason C++ beats Python.3
-mcpu / -march=nativeCompiler flag targeting the exact CPU for machine-specific speedups (SIMD etc.).3
Speedup factorBaseline time ÷ optimized time; the business metric for this task (e.g. 230×, 1440×).3, 5
Model dispatch (dict)Mapping model name → API client so one function routes to Ollama/OpenRouter/Groq.4
Compare harnessA repeatable Gradio UI / function to benchmark many models on your own task.4
GPT-OSS / Qwen Coder / DeepSeek CoderOpen-source code models; here open GPT-OSS beat some frontier models on the task.4, 5
Technical metricsModel-centric: loss, cross-entropy, perplexity, accuracy, latency, cost. Precise, trainable.5
Business metricsOutcome-centric: KPIs, ROI, user satisfaction. The real goal; noisier, slower.5
PerplexityModel's uncertainty over the next token; 1 = perfect confidence, higher = less certain.5
Kadane's algorithmO(n) single-pass maximum-subarray; the winning models reinvented it instead of naive O(n²).5
