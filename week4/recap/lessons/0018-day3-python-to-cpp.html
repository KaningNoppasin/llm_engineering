LLM Engineering ● Week 4 ● Day 3 Recap

Python → C++ with frontier models

A real business win: rewrite slow code in a fast language, measured by speedup.

Why this matters for the switch: this is the first time you point an LLM at a measurable engineering outcome — make code faster — and compare models on it. "I used the leaderboard to shortlist, then measured the real speedup" is a great interview story.

Today's win

You can prompt a frontier model to port Python to optimized C++, compile and time it, and compare models by the speedup they achieve.

The task

Take slow Python (estimating π with a 200-million-term Leibniz series, ~19s) and have an LLM rewrite it as high-performance C++. C++ compiles to native machine code, so the same algorithm runs orders of magnitude faster — and a smart model adds loop unrolling, threading, and CPU-specific flags on top.

Key concepts

  • Prompt design for translation. A firm system prompt ("convert Python to high-performance C++; respond with C++ only; identical output, fastest time") + a user prompt carrying the system info, compile command, and source.
  • Strip the fences. Models wrap code in ```cpp; you remove those markers before writing main.cpp.
  • Compile & run natively. clang++ -Ofast -mcpu=native (plus -flto, -DNDEBUG) then time the binary.
  • Models optimize differently. On this task: Claude ~148×, GPT-5 ~230× (reliable loop unrolling), Grok-4 ~1060× (aggressive threading), Gemini 2.5 Pro ~1440× (winner) via algorithm simplification + dynamic threading.
  • Leaderboard ≠ task winner. Gemini wasn't top of Artificial Analysis yet won this task — proving Day 1's lesson: validate on your own problem.
  • Reasoning effort helps. GPT models were called with reasoning_effort="high" for the harder optimization thinking.

The code shape to memorize

system_prompt = "Convert this Python to high-performance C++. Respond with C++ only; " \
                "produce identical output in the fastest possible time."

def port(client, model, python):
    effort = "high" if "gpt" in model else None
    r = client.chat.completions.create(
        model=model, reasoning_effort=effort,
        messages=[{"role": "system", "content": system_prompt},
                  {"role": "user",   "content": user_prompt_for(python)}])
    cpp = r.choices[0].message.content.replace("```cpp", "").replace("```", "")
    with open("main.cpp", "w") as f: f.write(cpp)

# compile to a native binary, then time it
subprocess.run(["clang++", "-std=c++17", "-Ofast", "-mcpu=native", "main.cpp", "-o", "main"])
subprocess.run(["./main"])
Interview-ready framing: "Why is the C++ 200× faster — is the model magic?" — No. Most of the win is compiled native code vs an interpreter; the model adds threading, loop unrolling, and -mcpu=native flags. Same algorithm, dramatically less overhead.
