Evaluation & the Rust challenge

Two kinds of metrics — and why the business one wins.

Why this matters for the switch: the engineers who get promoted connect a model's technical metrics to a business outcome. Knowing the difference — and that perplexity is not revenue — is what turns "I trained a model" into "I moved the number that mattered."

Today's win

You can name the two categories of model evaluation, define perplexity, and explain why an open-source model swept the harder Rust challenge.

The two kinds of evaluation

Technical (model-centric) metrics — loss, cross-entropy, perplexity, accuracy, latency, cost — are precise, fast, and trainable, but can miss the point. Business (outcome) metrics — KPIs, ROI, user satisfaction — are noisier and slower, but they're what you're actually paid to move. Connecting the two is the superpower.

Key concepts

  • Perplexity measures a model's uncertainty about the next token. 1 = perfect confidence; perplexity ~100 means roughly 100 equally-likely next tokens. Lower is more certain.
  • Technical metrics guide training in real time; business metrics validate that the thing actually works — use both, but optimize for the business outcome.
  • Harder task: Python → Rust. Generate 10,000 numbers via an LCG, find the maximum contiguous subarray sum, repeat 20× (Python baseline ~33s).
  • Algorithm beats brute force. Winners didn't just translate the naïve O(n²) loop — they recognized the problem and reimplemented Kadane's algorithm (O(n), single pass).
  • Rust's safety caught real bugs. Strict typing exposed an integer-overflow (32- vs 64-bit) that C++ would have let slide silently.
  • Open-source swept the podium. Only 3 of ~8 models produced correct runnable Rust; all used Kadane's: GPT-OSS 120B (304µs, winner), Grok-4 (317µs), GPT-OSS 20B (341µs) — about 111,000× faster than the Python baseline.

The idea to memorize

# naive O(n^2) — what slow translations produced
for i in range(n):
    current = 0
    for j in range(i, n):
        current += nums[j]
        best = max(best, current)

# Kadane's O(n) — what the WINNING models reinvented (shown in Rust)
//  let mut best = i64::MIN; let mut current = 0;
//  for x in nums { current = max(x, current + x); best = max(best, current); }

# compile Rust for speed:
//  rustc main.rs -C opt-level=3 -C target-cpu=native -C lto=fat
Interview-ready framing: "What does it mean that the win came from the algorithm?" — The biggest speedups weren't from a faster language but from O(n²)→O(n). The best models reasoned about the problem, not just the syntax — and a cheap open model did it best.
