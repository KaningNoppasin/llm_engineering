Open-source code models & a compare UI

Can open models match frontier on code? Build a UI and find out.

Why this matters for the switch: open code models can be far cheaper and run privately. Wiring several behind one dropdown and benchmarking them on a real task is precisely the "model comparison harness" an AI team needs — and a portfolio-ready build.

Today's win

You can route one conversion function to many models (Ollama, OpenRouter, Groq) and drive them all from a single Gradio dropdown UI.

The setup

Same Python→C++ task as Day 3, now with open-source code models (Qwen Coder, DeepSeek Coder, GPT-OSS) reached through three endpoints: Ollama (local), OpenRouter and Groq (APIs). One port(model, python) function dispatches to the right client by model name.

Key concepts

  • Pick candidates from a code leaderboard — HF's Big Code Models board + Artificial Analysis.
  • One client interface, many backends. Because all three speak the OpenAI API shape (Week 2!), a dict maps each model name to its client; the function looks up and calls.
  • Gradio compare UI. gr.Blocks with a Python input box, a C++ output box, a model dropdown, and a Convert button wired via .click(port, inputs, outputs).
  • Surprise result: open GPT-OSS 20B (~238×) beat GPT-5 (~233×) and Claude Sonnet 4.5 (~184×) on this task — though still behind Gemini (1440×) and Grok-4 (1060×).
  • Bigger ≠ better. GPT-OSS 120B underperformed its 20B sibling (~10× slower) because it emitted a bad #pragma that disabled loop unrolling; Qwen 2.5 (7B) failed outright.
  • This is a comparison harness. The real product isn't the C++ — it's the repeatable way to pit models against each other on your task.

The code shape to memorize

# map each model name to the client that serves it
clients = {
    "qwen2.5-coder":        ollama,
    "deepseek-coder-v2":     ollama,
    "qwen/qwen3-coder-30b":  openrouter,
    "openai/gpt-oss-120b":   groq,
}

def port(model, python):
    client = clients[model]                          # dispatch by name
    r = client.chat.completions.create(model=model, messages=messages_for(python))
    return r.choices[0].message.content.replace("```cpp", "").replace("```", "")

# one dropdown drives them all
with gr.Blocks() as ui:
    with gr.Row():
        python = gr.Textbox(label="Python", lines=28)
        cpp    = gr.Textbox(label="C++", lines=28)
    model   = gr.Dropdown(list(clients), label="Model")
    convert = gr.Button("Convert")
    convert.click(port, inputs=[model, python], outputs=[cpp])
ui.launch()
Interview-ready framing: "Are open models good enough?" — For code translation here, the best open model beat two frontier models at a fraction of the cost. The honest answer is "measure it on your task" — sometimes open wins, sometimes it fails outright (Qwen 2.5 did).
