Week 5 glossary

The RAG week: embeddings, chunking, retrieval, evaluation, advanced techniques. Print & pin.

New terms from Week 5. See also the Week 1, Week 2, Week 3, and Week 4 glossaries.

TermMeaningDay
RAGRetrieval-Augmented Generation: retrieve relevant context, inject into the prompt, then generate.1
Vector embeddingA list of numbers (300–3072 dims) representing the meaning of text.1
Encoder modelMaps text → one meaning vector (BERT, OpenAI text-embedding-3); vs generative/autoregressive models.1
Semantic similarityCloseness of meaning measured by vector distance (cosine), tolerant of wording.1
word2vecEarly embedding method; showed vector arithmetic (king − man + woman ≈ queen).1
Cosine similarityMetric ranking how aligned two vectors are; used to find nearest chunks.1
ChunkA fragment of a document, embedded and stored separately for precise retrieval.2
RecursiveCharacterTextSplitterLangChain splitter using chunk_size + chunk_overlap on natural boundaries.2
chunk_overlapText repeated between adjacent chunks so a fact isn't cut across a boundary.2
Embedding model dimsall-MiniLM-L6-v2 = 384, text-embedding-3-small = 1536, -large = 3072.2
Vector databaseStore optimized for similarity search: Chroma (local), FAISS (in-memory), Pinecone (managed).2
t-SNEProjects high-dim vectors to 2D/3D to visualize clustering / embedding quality.2
Retrievervectorstore.as_retriever() — embeds a query and returns top-k chunks via .invoke().3
top-kNumber of nearest chunks retrieved (default ~4); more context vs more noise/cost.3
Multi-turn retrievalRetrieve using combined conversation history so follow-ups keep the right entity in scope.3
MRRMean Reciprocal Rank: 1 ÷ position of the first relevant chunk, averaged; 1.0 = always first.4, 5
nDCGRanking metric rewarding all relevant chunks placed high, not just the first.4
Recall / keyword coverageWhether the needed facts appear in the top-k; favored over precision in RAG.4
LLM-as-a-judgeUsing an LLM to score answers vs a reference (accuracy/completeness/relevance) as structured output.4
Golden test dataCurated questions + expected keywords + reference answers (Pydantic) for repeatable eval.4
Spanning / holistic QsQuestions needing many chunks / whole-corpus understanding — RAG's weak spots.4
Semantic chunkingLLM splits documents on meaning (sections/topics) instead of fixed character counts.5
Query rewritingRewriting the user's question before retrieval to match the corpus better.5
Query expansionGenerating multiple query variants, retrieving each, then merging/de-duplicating.5
Re-rankingReordering retrieved candidates by true relevance (cross-encoder or LLM) after vector search.5
Cross-encoderA model that scores a (query, chunk) pair jointly — more accurate relevance than embedding distance.5
GraphRAGRAG over an entity/relationship graph; useful for relational queries.5
