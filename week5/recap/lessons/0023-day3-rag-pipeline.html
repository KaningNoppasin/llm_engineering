LLM Engineering ● Week 5 ● Day 3 Recap

The full RAG pipeline

Retriever + LLM + memory, wired into a chat UI — RAG end to end.

Why this matters for the switch: this is the deliverable — a working "chat with your documents" app. Being able to stand one up, with conversation memory, in a few dozen lines is a direct, demonstrable job skill.

Today's win

You can build the RAG core in ~5 lines — embed query, retrieve top-k chunks, inject, answer — and wrap it in a Gradio chat with conversation history.

The RAG core loop

Embed the query → search the vector DB → retrieve top-k chunks → stuff into the prompt → LLM answers. A retriever (from vectorstore.as_retriever()) packages the embed + search steps; the LLM answers grounded in the retrieved text.

Key concepts

  • The retriever abstraction. vectorstore.as_retriever() bundles the embedding model + Chroma into one object with .invoke(query) that returns Documents (each with .page_content and .metadata).
  • top-k. The retriever returns the k nearest chunks (default ~4; the lesson used k=5). More k = more context but more noise and cost.
  • Inject, then generate. Join the retrieved chunks into the system prompt, then call the LLM with that context + the user question.
  • Temperature 0 for RAG. You want faithful, deterministic answers from the context — not creativity. (Temperature ≠ creativity; that comes from the prompt.)
  • Conversation memory needs care. The LLM is stateless (Week 1), so you pass history — and crucially, retrieve using the combined history: "what's her salary?" after "who is Avery?" must still pull Avery's chunk.
  • Chunking can bite back. A chunk may contain the answer but miss context from the document top (e.g. an award mentioned without the person's full name) — a retrieval-quality problem.
  • Wrap it in Gradio. gr.ChatInterface(answer_question) gives a chat UI; the callback takes (question, history) (Week 2 again).

The code shape to memorize

# setup: load the persisted vector DB and build a retriever + LLM
vectorstore = Chroma(persist_directory=DB, embedding_function=embeddings)
retriever   = vectorstore.as_retriever(search_kwargs={"k": 5})
llm = ChatOpenAI(model=MODEL, temperature=0)

# the RAG core — five lines
def answer_question(question, history):
    docs = retriever.invoke(question)                      # top-k chunks
    context = "\n\n".join(d.page_content for d in docs)
    prompt = SYSTEM_TEMPLATE.format(context=context)
    reply = llm.invoke([SystemMessage(prompt), HumanMessage(question)])
    return reply.content

gr.ChatInterface(answer_question).launch()
Interview-ready framing: "Why does a follow-up question break naive RAG?" — Because you retrieve on the latest message alone. "What's her salary?" has no name to match. Fix: retrieve using the combined conversation (or a rewritten query — Day 5).
