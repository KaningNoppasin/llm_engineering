The upgrade menu

Day 4 gave you a number to beat. Day 5 improves it by fixing retrieval at every stage: better chunks going in, better queries going out, and a re-rank on the way back. Stacked together they took MRR from 0.73 to 0.91 — the right chunk is now first ~9 times in 10.

Key concepts

  • Semantic chunking. Let an LLM split documents on meaning (sections, topics) rather than fixed character counts — chunks become self-contained, so questions map cleanly.
  • Document pre-processing. Have an LLM add a headline + summary to each chunk before embedding, making it easier to retrieve.
  • Query rewriting. Rewrite the user's question before retrieval (clarify, add context) so it matches the corpus better — fixes the multi-turn problem from Day 3.
  • Query expansion. Generate several query variants, retrieve for each, then merge and de-duplicate — casting a wider net.
  • Re-ranking. Embedding similarity ≠ true relevance. After retrieval, a cross-encoder or LLM re-scores the candidates and reorders them; in the lesson a key chunk jumped from position 5 to 1.
  • GraphRAG models entities and relationships (e.g. employee→manager); useful for relational questions, though metadata often suffices.
  • Build without LangChain for control. Native Chroma + OpenAI makes each step explicit; multiprocessing parallelizes chunking (~10× faster ingest). Full pipeline ≈ $0.50 / run on 76 docs.

The code shape to memorize

# the advanced retrieval flow: rewrite -> expand -> retrieve -> merge -> RE-RANK
rewritten = rewrite_query(original_q, history)        # clarify / add context
cand = fetch(original_q) + fetch(rewritten)          # expansion
cand = dedupe(cand)

# re-rank candidates by ACTUAL relevance to the original question
def rerank(question, chunks):
    order = RankOrder.model_validate_json(ask_llm_to_rank(question, chunks)).order
    return [chunks[i - 1] for i in order]

best = rerank(original_q, cand)[:k]               # top-k after reordering
