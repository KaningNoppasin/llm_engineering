Many providers, one conversation

OpenAI, Claude, Gemini & OpenRouter — and the params that actually differ.

Why this matters for the switch: real AI teams mix providers — cheapest for bulk, smartest for hard calls, local for private. Knowing each SDK's quirks (and the unifying layers) is the difference between "I used the OpenAI tutorial" and "I architect model choice."

Today's win

You can call Claude's native API (noting how it differs from OpenAI), dial GPT-5's reasoning_effort, and run two models in conversation with each other.

The provider landscape

Week 1 showed one client hitting many OpenAI-compatible endpoints. Week 2 goes deeper: each frontier vendor also has a native SDK with its own shape, and aggregators like OpenRouter put 100+ models behind a single key.

Key concepts

  • OpenAI's client is the lingua franca. Point it at Anthropic, Gemini, DeepSeek, Groq via base_url — the increasingly standard way to stay provider-agnostic.
  • Anthropic's native API differs. client.messages.create(...) needs max_tokens (mandatory), takes system as a separate parameter (not a message), and you read response.content[0].text — not choices[0].
  • reasoning_effort is inference-time scaling. On GPT-5 (minimal/low/medium/high) it buys more "thinking" without a bigger model — a separate lever from model size.
  • OpenRouter = one key, many models. Address models as provider/model-name (e.g. z-ai/glm-4.5) through one OpenAI-compatible endpoint.
  • LangChain vs LiteLLM. LangChain is a heavyweight abstraction for complex workflows; LiteLLM is a thin wrapper that exposes per-call token usage and cost. Reach for LiteLLM when you want simplicity and visibility.
  • Prompt caching cuts cost. OpenAI caches automatically (~much cheaper repeat input); Anthropic is explicit. Put static content first, variable content last.
  • Multi-model conversations are just two message lists: each turn you rebuild the history with roles flipped so each model "sees" the other as the user.

The code shapes to memorize

# Anthropic NATIVE client — note the differences from OpenAI
from anthropic import Anthropic
claude = Anthropic()
response = claude.messages.create(
    model="claude-sonnet-4-5-20250929",
    system="You are concise.",      # system is a SEPARATE param
    messages=[{"role": "user", "content": "Hi"}],
    max_tokens=200,                  # REQUIRED on Anthropic
)
print(response.content[0].text)   # not choices[0].message.content

# GPT-5 reasoning effort (inference-time scaling)
openai.chat.completions.create(model="gpt-5-mini", messages=msgs, reasoning_effort="low")

# OpenRouter — one key, provider/model addressing
router = OpenAI(base_url="https://openrouter.ai/api/v1", api_key=key)
router.chat.completions.create(model="z-ai/glm-4.5", messages=msgs)
Interview-ready framing: "How do you keep code portable across providers?" — Use the OpenAI client with swappable base_url, or a wrapper like LiteLLM/OpenRouter; isolate the few native-SDK differences (Anthropic's max_tokens, separate system, content[0].text) behind one function.
