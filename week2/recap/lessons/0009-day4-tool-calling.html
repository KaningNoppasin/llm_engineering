LLM Engineering ● Week 2 ● Day 4 Recap

Tool calling — no magic, just prompts

The model asks you to run a function. You run it and hand back the result.

Why this matters for the switch: tool calling is the single most important pattern in modern AI engineering — it's how LLMs touch databases, APIs, and the real world. Every "agent" is built on this round-trip. Nail it and you can build genuinely useful systems.

Today's win

You can explain the tool-calling round-trip end to end, and write the while finish_reason == "tool_calls" loop that powers it.

The demystification

The LLM never runs your code. When it "calls a tool," it just emits a structured message saying "please run get_ticket_price("London") and tell me the result." Your code runs the function, appends the result to the conversation, and calls the model again. The model then writes the final answer using that result. No magic — a two-step prompt exchange.

The round-trip, step by step

  • 1. Describe your tools as JSON schema and pass them via tools=. Each has a name, description (the model reads this to decide when to call it), and parameters with required fields.
  • 2. Detect the request. If response.choices[0].finish_reason == "tool_calls", the reply is a function request, not text.
  • 3. Run the function. Parse tool_call.function.arguments (a JSON string) and call your real Python function.
  • 4. Append the result as a message with role: "tool" and the matching tool_call_id — the ID correlates the result to the specific request.
  • 5. Call the model again with the expanded history. It now answers in natural language.
  • Multiple & sequential tools: loop over message.tool_calls for several at once, and use while (not if) so the model can chain more calls after seeing results.
  • Real backends: swap the mock lookup for SQLite (with parameterized ? queries) and the model can query a real database.

The code shape to memorize

# 1. tool schema
tools = [{
    "type": "function",
    "function": {
        "name": "get_ticket_price",
        "description": "Get the round-trip price to a destination city",
        "parameters": {
            "type": "object",
            "properties": {"destination_city": {"type": "string"}},
            "required": ["destination_city"],
        },
    },
}]

# 2-5. the round-trip loop
response = openai.chat.completions.create(model=MODEL, messages=messages, tools=tools)
while response.choices[0].finish_reason == "tool_calls":
    msg = response.choices[0].message
    messages.append(msg)                          # the assistant's tool request
    for call in msg.tool_calls:
        args = json.loads(call.function.arguments)  # arguments are a JSON string
        result = get_ticket_price(args["destination_city"])
        messages.append({"role": "tool", "content": result,
                         "tool_call_id": call.id})   # must match the request id
    response = openai.chat.completions.create(model=MODEL, messages=messages, tools=tools)
return response.choices[0].message.content
The four things people get wrong: (1) forgetting to append the assistant's tool-request message before the tool result; (2) omitting tool_call_id; (3) using if instead of while (breaks multi-step chains); (4) forgetting to re-pass tools= on the second call.
