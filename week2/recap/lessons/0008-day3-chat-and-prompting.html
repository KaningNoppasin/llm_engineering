Chatbots & prompt steering

gr.ChatInterface, the messages list, multi-shot, and RAG's first glimpse.

Why this matters for the switch: a chatbot is the default shape of most LLM products. Knowing exactly how history flows through the messages list — and how to steer behavior with examples and injected context — is bread-and-butter AI engineering.

Today's win

You can build a streaming chatbot in one line of UI code, and steer it with multi-shot examples and context injected into the system prompt.

The chatbot loop

gr.ChatInterface gives you a full chat UI for free. Your job is one function, chat(message, history): Gradio hands you the new message and the prior turns, and you rebuild the messages list the LLM expects, then stream the reply.

Key concepts

  • The messages list is always the same recipe: [system] + history + [user]. Gradio supplies history; you prepend the system message and append the new user turn.
  • History is a list of role/content dicts. With type="messages", Gradio passes OpenAI-style {"role": ..., "content": ...} entries (sometimes with extra metadata keys you may need to strip for other providers).
  • The system message lives in your code, not the UI — Gradio doesn't know about it, so you must prepend it every call.
  • Multi-shot prompting steers behavior by putting example Q&A pairs in the system prompt (one example = one-shot, several = multi-shot). Examples beat adjectives.
  • RAG, the primitive version. Conditionally inject relevant facts into the system prompt based on the user's message (e.g. detect "belt" → add store-policy text). That's retrieval- augmented generation in its simplest, hand-rolled form.
  • Streaming again: yield the accumulating response instead of return — same generator trick as Day 2.

The code shape to memorize

def chat(message, history):
    # history is [{"role":..., "content":...}, ...] from Gradio
    messages = [{"role": "system", "content": system_message}] \
             + history \
             + [{"role": "user", "content": message}]

    stream = openai.chat.completions.create(model=MODEL, messages=messages, stream=True)
    response = ""
    for chunk in stream:
        response += chunk.choices[0].delta.content or ""
        yield response

gr.ChatInterface(fn=chat, type="messages").launch()

# primitive RAG: inject context conditionally before the call
if "belt" in message.lower():
    system_message += " The store does not sell belts; suggest alternatives."
Interview-ready framing: "What is RAG, simply?" — Fetch the facts relevant to this query and put them in the prompt before generating. Today's keyword-injection is the toy version; Week 5 replaces the if with a vector search over an embedded knowledge base.
