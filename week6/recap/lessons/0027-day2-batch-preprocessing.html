The 5-step process & batch processing

A disciplined path from business problem to production — and cheap bulk inference.

Why this matters for the switch: a method for taking an AI problem from "understand" to "in production" is what turns a coder into an AI engineer. And batch processing — 22,000 LLM calls for under $1 — is the kind of cost instinct that makes you valuable on a team.

Today's win

You can name the 5-step process for applying LLMs to a business problem, and run a cheap bulk job via a JSONL batch API.

The 5-step process

A repeatable way to apply AI to a real problem: Understand → Prepare → Select/Customize → Apply → Productionize. Start from the business requirement and a success metric — not "let's build an agent." Build a non-LLM baseline in Prepare so you can prove you actually improved.

Key concepts

  • Understand first. Pin down the problem and how you'll measure success before choosing any architecture.
  • Prepare = data + baseline. Clean the data and build a simple baseline (Day 3) to beat.
  • LLMs can pre-process data. Turn messy scraped descriptions into tight structured fields (title / category / brand / details) with a system prompt — annotation that used to need humans.
  • Batch mode. Queue many requests in a JSONL file (one JSON object per line), submit asynchronously with a completion window, fetch results later. Providers give ~50% off vs synchronous calls.
  • The economics. ~22,000 requests for under $1 on Groq batch mode — pennies per thousand for small open models.
  • Match results by custom_id. Each request carries an ID so you can line up outputs with inputs when the batch returns.
  • Productionize = MLOps. Step 5 is ongoing: monitor for model drift (real data diverges from training data over time) and retrain/evaluate continuously.

The code shape to memorize

# 1. write a JSONL batch file — one request object per line
def to_jsonl(item):
    body = {"model": "openai/gpt-oss-20b",
            "messages": [{"role": "system", "content": SYS},
                         {"role": "user", "content": item.full}]}
    return json.dumps({"custom_id": str(item.id), "method": "POST",
                       "url": "/v1/chat/completions", "body": body})

# 2. upload -> submit batch -> retrieve when done
fid = groq.files.create(file=open("batch.jsonl", "rb"), purpose="batch").id
bid = groq.batches.create(input_file_id=fid, endpoint="/v1/chat/completions",
                          completion_window="24h").id
out = groq.files.content(groq.batches.retrieve(bid).output_file_id)
Interview-ready framing: "When do you use batch vs synchronous calls?" — Batch when latency doesn't matter and volume is high (data prep, bulk labeling, offline scoring): you trade immediacy for ~half the cost. Synchronous for interactive, user-facing requests.
