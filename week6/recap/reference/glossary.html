Week 6 glossary

Data, baselines & fine-tuning: the capstone toolkit. Print & pin.

New terms from Week 6. See also the Week 1, Week 2, Week 3, Week 4, and Week 5 glossaries.

TermMeaningDay
GeneralizationA model's ability to predict well on unseen data — the core goal of training.1
Data curationCleaning, filtering, and balancing a dataset; often beats hyperparameter tuning for results.1
Transfer learningAdapting a pre-trained model to your task — far cheaper than training from scratch.1
Data leakageTrain/test overlap (e.g. duplicates) that inflates validation scores and hides overfitting.1
Weighted samplingSampling to rebalance a skewed distribution (e.g. weight by price, down-weight a category).1
Train / val / test splitLearn / tune / final-check pools; test is held untouched until the end.1
5-step processUnderstand → Prepare → Select/Customize → Apply → Productionize.2
MLOpsProductionizing & maintaining ML: monitoring, evaluation, retraining.2
Model driftPerformance decay as live data diverges from the training distribution.2
Batch modeQueue many requests asynchronously (JSONL) for ~50% lower cost vs synchronous.2
JSONLJSON Lines: one complete JSON object per line; used for batch & fine-tune files.2, 5
custom_idPer-request ID in a batch so outputs can be matched back to inputs.2
Baseline modelA simple model (even random) that fancier approaches must beat.3
MAEMean Absolute Error: average size of the prediction error (here, in dollars).3, 4
R²Variance explained: 0 = no better than the average, 1 = perfect, negative = worse.3, 4
Feature engineeringCrafting good input features; for traditional ML it matters more than the algorithm.3
Bag-of-Words / CountVectorizerTurns text into word-count vectors (top ~2,000 words, no stop-words).3
Random ForestMany independent decision trees, averaged.3
XGBoostGradient-boosted trees built sequentially, each correcting the last's errors.3
Training loopForward pass → loss → backward pass → optimizer step, over batches/epochs.4
Epoch / batch size / learning rateOne pass over data / items per step / step size — core hyperparameters.4
Loss functionMeasures prediction error (e.g. MSELoss); its gradient drives learning.4
Human baselineHuman performance on the task, used as a difficulty yardstick.4
Zero-shotUsing a model on a task with no task-specific training, just a prompt.4
Supervised fine-tuning (SFT)Training a model on input→output pairs to adapt behavior (style/format), not knowledge.5
LoRALow-Rank Adapters: small trainable matrices fine-tuned instead of the whole model.5
Fine-tune vs RAG vs promptBehavior → fine-tune; knowledge → RAG; cheapest first → prompt/few-shot.5
