QLoRA & low-rank adapters

Fine-tune a 3B model on a free GPU by training 0.6% of it.

Why this matters for the switch: QLoRA is the technique that makes fine-tuning affordable — it's how small teams adapt open models without a data-center. "I fine-tuned Llama with QLoRA on one GPU" is a concrete, in-demand line on a CV.

Today's win

You can configure QLoRA — 4-bit base + LoRA adapters — and explain what r, lora_alpha, and target_modules each do.

The two ideas: LoRA + Q

LoRA (Low-Rank Adaptation): freeze the entire base model and train tiny adapter matrices that get added into a few layers. QLoRA adds the "Q": quantize the frozen base to 4-bit (13GB → ~2.2GB) while the adapters stay full precision. Result: you train ~0.6% of the parameters and the whole thing fits on a free Colab T4.

Key concepts

  • Freeze the base, train adapters. The 3B base weights never update — only the small LoRA A·B matrices do, so gradients/optimizer state are tiny.
  • r (rank) sets adapter capacity (common: 8, 16, 32, up to 256). Higher r = more trainable parameters and fit, but slower.
  • lora_alpha scales the adapter's contribution; rule of thumb alpha = 2·r.
  • target_modules picks which layers get adapters — start with the attention projections q_proj, k_proj, v_proj, o_proj; add MLP layers for more capacity.
  • lora_dropout regularizes the adapters to fight overfitting.
  • 4-bit barely hurts. nf4 spends its 16 levels where weights actually cluster (normal distribution), so the model stays ~95%+ as capable — Week 3's quantization, now for training.
  • The savings are dramatic. r=32 → ~18M trainable params (0.6% of 3B, ~73MB on disk) vs the full 3B; a heavy r=256 + MLP variant is still only ~13% of the model.

The code shape to memorize

from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model

# quantize the BASE model to 4-bit (the "Q" in QLoRA)
bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                         bnb_4bit_compute_dtype=torch.bfloat16, bnb_4bit_use_double_quant=True)
base = AutoModelForCausalLM.from_pretrained("meta-llama/Llama-3.2-3B",
                                            quantization_config=bnb, device_map="auto")

# attach trainable LoRA adapters (the rest stays frozen)
lora = LoraConfig(r=32, lora_alpha=64, lora_dropout=0.05,
                  target_modules=["q_proj", "k_proj", "v_proj", "o_proj"])
model = get_peft_model(base, lora)   # now only ~0.6% of params are trainable
Interview-ready framing: "Why not just fine-tune the whole model?" — Memory. Full fine-tuning a 3B model needs the weights plus gradients and optimizer state (often 4× the model). QLoRA keeps the base frozen and 4-bit, so you only pay for the tiny adapters' gradients.
