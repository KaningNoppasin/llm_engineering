Hyperparameters & the SFT Trainer

The dials that govern training — and the tool that runs the loop for you.

Why this matters for the switch: hyperparameters are where fine-tuning goes right or wrong, and "I tuned the learning rate / used a cosine schedule / tracked it in W&B" is the vocabulary of someone who has actually trained models — not just called an API.

Today's win

You can set the core training hyperparameters, launch a QLoRA run with TRL's SFTTrainer, and track it live in Weights & Biases.

The hyperparameters that matter

  • Epochs — full passes over the data (1–3). Each epoch reshuffles batches for fresh gradient signal.
  • Batch size — items per gradient step; bump it up to fill the GPU (powers of 2: 32, 256).
  • Learning rate — the step size (~1e-4). Too high overshoots/diverges; too low crawls. Tune in powers of 10.
  • LR scheduler (cosine + warmup) — start low, ramp up, then decay: explore broadly early, refine precisely late.
  • Gradient accumulation — sum gradients over N steps before updating, simulating a bigger batch without running out of memory.
  • Optimizer (paged_adamw) — Adam with momentum, paged to survive memory spikes; converges faster than plain SGD.
  • SFTTrainer (TRL) bundles model + dataset + LoRA config + SFTConfig and runs the forward/backward/optimize loop for you.
  • Weights & Biases (wandb) logs loss, learning rate, and metrics per step so you watch training live and compare runs.

The code shape to memorize

from trl import SFTTrainer, SFTConfig
import wandb; wandb.init(project="pricer", name=run_name)

args = SFTConfig(
    num_train_epochs=1,
    per_device_train_batch_size=32,
    gradient_accumulation_steps=1,
    learning_rate=1e-4,
    lr_scheduler_type="cosine",
    warmup_ratio=0.03,
    optim="paged_adamw_32bit",
    max_seq_length=128,
    logging_steps=5, save_steps=100,
    report_to=["wandb"],          # live tracking
)

trainer = SFTTrainer(model=base, train_dataset=train, eval_dataset=val,
                     peft_config=lora, args=args)
trainer.train()                     # runs the whole loop
Interview-ready framing: "Why a cosine schedule with warmup?" — Warmup avoids a big early step that destabilizes fresh weights; the cosine decay then lets the model take big exploratory steps early and fine, careful steps near the end. A constant LR does neither well.
