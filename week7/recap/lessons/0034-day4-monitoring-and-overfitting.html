Monitoring & catching overfitting

Read the loss curves, train on 800K points, and pick the best checkpoint.

Why this matters for the switch: reading a training run — spotting overfitting, choosing a checkpoint, not wasting a 21-hour GPU run — is the operational maturity that separates "I can train a model" from "I can train a model that ships."

Today's win

You can read training vs validation loss in Weights & Biases, recognize overfitting, and pick the best checkpoint instead of the last one.

The one rule of monitoring

Training loss alone lies. It always falls. What tells the truth is validation loss on held-out data. When training loss keeps dropping but validation loss rises, the model is memorizing, not learning — that's overfitting.

Key concepts

  • Healthy curve: train and validation loss fall together. Overfitting: they diverge — train ↓, validation ↑.
  • The epoch-boundary spike. Validation loss jumping up when a new epoch starts is a classic overfitting signature — the model has memorized prior-epoch examples.
  • Scale of the full run. 800K points × 3 epochs = 2.4M examples on a Colab A100 (80GB, ~70GB used), ~21 hours (under Colab's 24h cap).
  • Save checkpoints during training. push_to_hub=True + save_steps writes checkpoints to the HF hub every N steps — don't wait for the end to pick a model.
  • Early stopping by selection. The best model is the checkpoint with the lowest validation loss (here ~step 6200, mid-epoch-2), not the final one — recover it via the HF commit history.
  • Keep test data sacred. Choosing a checkpoint on validation loss is implicit training on validation; the test set must stay untouched for an honest final number.
  • The adapter is small. The best checkpoint is ~1.56GB of LoRA adapters — not the whole model.

The code shape to memorize

# in SFTConfig: validate + checkpoint to the Hub during training
args = SFTConfig(
    eval_strategy="steps", save_strategy="steps", save_steps=200,
    per_device_train_batch_size=256,        # big batch to fill the A100
    learning_rate=1e-3, lr_scheduler_type="cosine",
    push_to_hub=True,                        # every checkpoint -> HF hub
    report_to=["wandb"],
)

# later: load the BEST checkpoint by its hub revision (commit id)
model = PeftModel.from_pretrained(base, hub_repo, revision=best_commit)
Interview-ready framing: "How did you know when to stop?" — Watch validation loss in W&B; it bottomed mid-epoch-2 then rose at epoch 3 (overfitting). The deliverable is the checkpoint at that minimum — saved live via push_to_hub, not the final-step weights.
