LLM Engineering ● Week 7 ● Day 2 Recap

Dataset prep & the base model

Shape the data for the model — and measure the untrained baseline first.

Why this matters for the switch: fine-tuning lives or dies on data shape. The small decisions here — base vs chat, prompt template, token cutoff, rounding the target — are exactly the "why did your fine-tune work?" details an interviewer probes.

Today's win

You can format a fine-tuning dataset for a base model, optimize its token length, and test the untrained model to get a baseline to beat.

Base, not chat

You fine-tune the base Llama 3.2, not the chat variant. A base model just predicts the next token after any text — perfect for a single-instruction task. A chat model expects system/user/assistant structure you don't need here, and does worse.

Key concepts

  • The prompt template. "How much does this cost to the nearest dollar? {desc} Price is $" — the model completes with the number. The answer is appended for training.
  • Llama tokenizes 0–999 as single tokens. So predicting a price becomes (almost) a one-token task — a big reason Llama suits this problem.
  • Round prices in training data. Token prediction weights every token equally; keeping cents makes the model waste capacity on them. Round to whole dollars for training, keep true prices in test for a fair benchmark.
  • Optimize token length. Max item is ~245 tokens; cut descriptions to ~110 (truncating only ~5.7% of items). GPU memory scales with sequence length, so shorter = faster/cheaper.
  • Pick a power-of-2 max length. Prompt + 110 + "Price is $" ≈ 126 → round to 128 for clean memory alignment.
  • Test the base model first. Untrained Llama scores ~$110.72 MAE — worse than Week 6's constant-guess baseline ($106). That's your "before" number; fine-tuning has to beat it.
  • Standard splits. prompt/completion columns; 20k/1k/1k (light) or 10× for the full run.

The code shape to memorize

# build the training prompt; round the price for the target
def make_prompt(item, tokenizer, max_tokens=110):
    desc = tokenizer.decode(tokenizer.encode(item.summary)[:max_tokens])
    prompt     = f"How much does this cost to the nearest dollar?\n{desc}\nPrice is $"
    completion = str(round(item.price))     # whole dollars for training
    return prompt, completion

# baseline: what does the UNTRAINED base model predict?
inputs = tokenizer(prompt, return_tensors="pt").to("cuda")
with torch.no_grad():
    out = base.generate(**inputs, max_new_tokens=5)
print(tokenizer.decode(out[0, inputs.input_ids.shape[1]:]))
Interview-ready framing: "Why round the prices?" — The model predicts tokens, not numbers. "$59.99" is several tokens of which only the magnitude matters; rounding to "$60" focuses the learning signal on getting the dollar amount right instead of memorizing cents.
