Week 7 glossary

QLoRA fine-tuning: adapters, hyperparameters, training, cross-entropy. Print & pin.

New terms from Week 7. See also the Week 1, 2, 3, 4, 5, and 6 glossaries.

TermMeaningDay
LoRALow-Rank Adaptation: freeze the base model, train small adapter matrices added into layers.1
QLoRALoRA with a 4-bit quantized base model — fits huge models on one GPU.1
Adapter (A·B matrices)The small trainable low-rank matrices LoRA adds; multiplied and scaled into a target layer.1
r (rank)Adapter capacity (8/16/32…256); higher = more trainable params and fit, slower.1
lora_alphaScaling applied to the adapter; convention alpha = 2·r.1
target_modulesLayers that get adapters — usually attention q/k/v/o, optionally MLP.1
lora_dropoutDropout on the adapters to reduce overfitting.1
PEFTParameter-Efficient Fine-Tuning — the HF library/family (LoRA etc.).1, 5
Base vs chat modelBase predicts next tokens for any text; chat expects dialogue structure. Fine-tune the base here.2
Prompt/completion formatTraining pairs: a prompt ending in "Price is $" and the completion (the price).2
Token-length cutoffTruncating inputs (e.g. 110 tokens) to save GPU memory/time; pad to a power of 2 (128).2
EpochOne full pass over the training data; batches reshuffled each epoch.3
Learning rateStep size of weight updates (~1e-4); too high diverges, too low crawls.3
LR scheduler (cosine + warmup)Ramp up then decay the learning rate over training.3
Gradient accumulationSum gradients over N steps to simulate a bigger batch without more memory.3
Optimizer (paged_adamw)Adam with momentum, memory-paged; converges faster than plain SGD.3
SFTTrainer / SFTConfigTRL classes that run the supervised fine-tuning loop from model + data + LoRA + args.3
Weights & Biases (wandb)Experiment tracker: logs loss, LR, metrics per step; compare runs.3, 4
Training vs validation lossTrain loss always falls; validation loss on held-out data reveals real generalization.4
Overfitting signatureTrain loss ↓ while validation loss ↑ (often spiking at a new epoch) = memorizing.4
Checkpoint / push_to_hubSaving model state to the HF hub every N steps during training.4
Best checkpoint selectionShip the lowest-validation-loss checkpoint, not the final step.4
SoftmaxTurns LM-head logits into a probability distribution over the vocabulary (sums to 1).5
Cross-entropy loss−log(probability of the true next token); the standard LLM training loss.5
BackpropagationChain-rule gradient computation; here only the LoRA adapters receive gradients.5
Top-k weighted estimateAveraging top-k token values by probability for a sharper numeric prediction.5
