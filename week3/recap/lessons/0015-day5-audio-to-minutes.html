LLM Engineering ● Week 3 ● Day 5 Recap

Audio → meeting minutes

Chaining a frontier transcriber with an open generator — the capstone build.

Why this matters for the switch: the most valuable engineers combine models — closed where it's best, open where it's cheapest. This audio→minutes app is a complete, portfolio-ready product that proves you can architect a multi-model pipeline.

Today's win

You can transcribe audio with Whisper, summarize it into structured minutes with an open Llama model, and stream the output token-by-token with TextStreamer.

The two-stage pipeline

Audio → Whisper (transcription) → Llama 3.2 (generation) → markdown minutes. Stage one uses a frontier speech model; stage two uses an open-source LLM you run yourself. Each stage does one job well — the essence of pipeline thinking.

Key concepts

  • Whisper for speech-to-text. Run it free via a HF automatic-speech-recognition pipeline, or via OpenAI's paid API (faster: ~27s vs ~2min in the lesson, for ~$0.02).
  • Open LLM for generation. Feed the transcript to Llama 3.2 (3B) with a system prompt that demands structured minutes: summary, discussion points, action items with owners.
  • Generation is token-by-token. One forward pass yields ~128k logits (one per vocab token); pick one, append, repeat. Each new token is conditioned on all prior ones — that's the coherence.
  • Temperature tunes the pick: 0 = greedy/deterministic, higher = more varied, sampling from lower-probability tokens.
  • TextStreamer decodes and prints tokens as they're generated — real-time output instead of waiting for the whole response.
  • tokenizer.pad_token = tokenizer.eos_token — a common Llama setup line so padding doesn't confuse generation.
  • It all runs on a free Colab T4 thanks to Day 4's 4-bit quantization (open generation stage is the heavy part).

The code shape to memorize

# stage 1: transcribe audio with Whisper (free HF pipeline)
asr = pipeline("automatic-speech-recognition", model="openai/whisper-small.en")
transcript = asr("meeting.wav")["text"]

# stage 2: summarize into minutes with an open LLM, streamed
from transformers import TextStreamer
messages = [
    {"role": "system", "content": "Produce markdown minutes: summary, points, action items."},
    {"role": "user",   "content": f"Transcript:\n{transcript}"},
]
inputs = tok.apply_chat_template(messages, return_tensors="pt").to("cuda")
streamer = TextStreamer(tok)
model.generate(inputs, streamer=streamer, max_new_tokens=1024)
Interview-ready framing: "When mix closed and open models?" — Use the best frontier model for the hard, low-volume step (accurate transcription) and a cheap open model for the bulk generation you'll run often. You optimize cost and quality per stage, not for the whole app at once.
