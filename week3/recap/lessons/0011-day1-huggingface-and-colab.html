Hugging Face & Colab GPUs

Leaving the API behind — running open models on rented hardware.

Why this matters for the switch: Weeks 1–2 rented intelligence through APIs. Week 3 is where you run the models yourself. Owning the weights, the GPU, and the inference is the skill that separates "API caller" from "AI engineer" on a CV.

Today's win

You can attach a free cloud GPU in Google Colab, authenticate to Hugging Face with a token, and generate an image from an open diffusion model.

The two halves of Hugging Face

Hugging Face is both a platform and a library. The platform (the website) hosts Models, Datasets, and Spaces (hosted Gradio/Streamlit apps) — think "GitHub for AI", with 2M+ models. The libraries are Python packages that download and run those models.

Key concepts

  • Three core libraries. huggingface_hub (download/connect to the Hub), datasets (efficient data handling), and transformers (run the models). Advanced ones come later: PEFT, TRL, Accelerate.
  • Google Colab = a notebook on Google's GPUs. A free T4 (15 GB VRAM) or a paid A100 (40 GB, ~$0.50/hr). The "runtime" is your Python kernel + the attached hardware.
  • Check the GPU with !nvidia-smi — confirms which card you actually got (the free tier can silently drop you to CPU).
  • HF auth via a token. Create a token with write permission (format hf_…), store it in Colab Secrets as HF_TOKEN, then login() in code.
  • Gated models. Some models (Meta's Llama) require accepting a license before your token can download them; others (DeepSeek, Qwen) are open access.
  • Diffusion models generate images: Stable Diffusion XL (~30 steps) or FLUX. More num_inference_steps = slower but potentially sharper; Turbo variants need ~4.
  • Runtime hygiene. "Restart Session" clears variables but keeps pip installs; "Delete Runtime" wipes everything (and you lose GPU memory leaks with it).

The code shape to memorize

# authenticate to Hugging Face using a Colab secret
from google.colab import userdata
from huggingface_hub import login
login(token=userdata.get("HF_TOKEN"))

# generate an image with a diffusers pipeline on the GPU
from diffusers import DiffusionPipeline
pipe = DiffusionPipeline.from_pretrained("stabilityai/stable-diffusion-xl-base-1.0")
pipe.to("cuda")                         # move model onto the GPU
image = pipe("a red panda coding, pop-art", num_inference_steps=30).images[0]
Interview-ready framing: "Why run open-source locally instead of just calling GPT?" — cost at scale, data privacy, no rate limits, full control, and the ability to fine-tune. The tradeoff is you manage the GPU and memory yourself.
