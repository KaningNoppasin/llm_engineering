Quantization & model internals

The low-level API, 4-bit weights, and what's actually inside a decoder layer.

Why this matters for the switch: quantization is what lets a billion-parameter model fit on a free GPU — the single most practical trick for running open models on a budget. And being able to describe a decoder layer in an interview proves you understand what you deploy.

Today's win

You can load an open LLM in 4-bit with BitsAndBytesConfig, generate from it with the low-level API, and name the parts of a decoder layer.

Two big ideas

1. The low-level API. Below pipeline() sits AutoModelForCausalLM + the tokenizer, giving you control over loading, quantization, and generation. "Causal LM" = predicts the next token from prior tokens only.
2. Quantization. Store each weight in 4 bits instead of 16/32, cutting memory ~4× with little quality loss. The analogy: a dimmer switch with 16 discrete levels instead of smooth.

Key concepts

  • BitsAndBytesConfig sets up 4-bit loading: load_in_4bit=True, nf4 quant type (assumes normally-distributed weights), bfloat16 compute, double-quant for extra savings.
  • device_map="auto" places the model across available GPU/CPU memory for you.
  • The generate flow: apply_chat_template → move tokens to cuda → model.generate(..., max_new_tokens=N) → tokenizer.decode.
  • Inside the model: an embedding layer maps each of 128,256 vocab IDs to a dense vector (2,048 dims in Llama 3.2-1B), then a stack of decoder layers.
  • A decoder layer = self-attention (query/key/value/output projections) + an MLP (up-project 2048→8000, gate, down-project 8000→2048) + layer norm.
  • Non-linearity is mandatory. Without an activation (e.g. SiLU/ReLU) in the MLP, stacked linear layers collapse into a single linear map — every parameter would be redundant.
  • The LM head is the final layer: 2,048 dims → 128,256 logits, a probability over the next token.

The code shape to memorize

from transformers import AutoModelForCausalLM, BitsAndBytesConfig
import torch

bnb = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_compute_dtype=torch.bfloat16,
    bnb_4bit_use_double_quant=True,
)

model = AutoModelForCausalLM.from_pretrained(
    "meta-llama/Llama-3.2-1B-Instruct",
    quantization_config=bnb, device_map="auto",
)

inputs = tok.apply_chat_template(messages, return_tensors="pt").to("cuda")
out = model.generate(inputs, max_new_tokens=80)
print(tok.decode(out[0]))
Interview-ready framing: "Why does 4-bit barely hurt quality?" — Weights are roughly normally distributed, so nf4 spends its 16 levels where most weights actually live. You trade a tiny bit of precision for ~4× the model on the same GPU.
