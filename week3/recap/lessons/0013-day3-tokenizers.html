Tokenizers & chat templates

Every model has its own private dictionary — and its own way to format a chat.

Why this matters for the switch: when you run open models yourself, you own tokenization. Get the tokenizer or chat template wrong and the model outputs garbage. This is the layer Weeks 1–2 hid from you — and a favorite interview probe.

Today's win

You can load a model's tokenizer, encode/decode text, and format a conversation with apply_chat_template the exact way that model was trained to expect.

The core idea

A tokenizer converts text ⇄ token IDs (numbers the model actually consumes). Crucially, every model has its own tokenizer and vocabulary — the same word maps to different IDs in Llama vs Phi-4 vs Qwen. Decode Llama's IDs with Phi's tokenizer and you get nonsense.

Key concepts

  • AutoTokenizer.from_pretrained(model) loads the right tokenizer for any model — you never pick it manually.
  • encode / decode are inverses: text → token IDs → text.
  • Special tokens are reserved IDs that don't map to language: BOS (begin), EOS (end), and role/header markers. They tell the model about structure.
  • They work because of training, not magic. The model learned to treat these tokens consistently from billions of examples — nothing in the architecture hard-codes them.
  • apply_chat_template(messages, …) turns an OpenAI-style message list into the single token string that model expects, inserting the right special tokens automatically.
  • Templates differ per model. Llama injects a knowledge-cutoff date and header markers; Phi-4 is simpler; DeepSeek orders things differently. Use each model's own template.
  • Vocab size is a tradeoff. Llama 3.1 has 128,256 tokens (128,000 + 256 reserved). Bigger vocab → rare words in fewer tokens; code models (Qwen/Starcoder) tune vocab for syntax.

The code shape to memorize

from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("meta-llama/Llama-3.1-8B-Instruct")

ids  = tok.encode("Tokenizers convert text to numbers")   # text  -> [ids]
text = tok.decode(ids)                                    # [ids] -> text

# format a conversation the way THIS model was trained to read it
messages = [
    {"role": "system", "content": "You are helpful."},
    {"role": "user",   "content": "Tell a joke."},
]
prompt = tok.apply_chat_template(messages, tokenize=False,
                                     add_generation_prompt=True)
Interview-ready framing: add_generation_prompt=True appends the assistant header so the model knows it's its turn to speak. Forget it and the model may try to continue the user's turn instead. The chat template is why you can't just paste raw text into a chat model and expect good results.
