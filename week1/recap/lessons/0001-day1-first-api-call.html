LLM Engineering ● Week 1 ● Day 1 Recap

Your first LLM call & the web summarizer

From a model running on your laptop to a working OpenAI API pipeline.

Why this matters for the switch: every LLM product you will ever build is, underneath, this exact shape — build a list of messages, send them to a model, read the reply. Day 1 is the atom. Master it and the rest of the course is composition.

Today's win

You can call a frontier model from Python and explain why a request is split into a system prompt and a user prompt.

The core idea

An LLM doesn't "run" inside your code — you send it text and it sends text back over an API. Day 1 shows the two ways to get a model to talk to you: locally with Ollama (open-source models on your own machine, free, private, smaller) and via the cloud with OpenAI's Chat Completions API (frontier models, pay-per-token, far more capable). Same mental model, different muscle.

Key concepts

  • Two places models live. Ollama downloads open-source models (Gemma, Phi-3, Llama) and runs them locally; OpenAI runs frontier models (GPT-5, GPT-4.1) in the cloud behind an API.
  • A request is a list of messages. Each message is a dict with a role (system or user) and content. The model predicts the next message.
  • System vs user prompt. The system prompt sets the job, tone, and rules ("you are a summarizer; reply in markdown"). The user prompt carries the actual data or question for this call.
  • Secrets live in .env. Your key (format sk-proj-…) goes in a .env file that is never committed. load_dotenv() reads it; the OpenAI() client picks up OPENAI_API_KEY automatically.
  • The toolchain. uv (a Rust-based package manager) builds the virtual environment in minutes; Cursor + a Jupyter kernel pointed at .venv is where you run cells.
  • Model tiers are a cost/speed dial. Cheap-and-fast (gpt-5-nano / gpt-4.1-nano) for simple jobs like summarizing; bigger models when you need more quality.
  • The summarizer pipeline. Fetch a page's text → build system + user messages → call the API → read response.choices[0].message.content → render as markdown.

The code shape to memorize

# 1. client reads OPENAI_API_KEY from your .env automatically
from openai import OpenAI
from dotenv import load_dotenv
load_dotenv()
openai = OpenAI()

# 2. a request is just a list of role/content messages
messages = [
    {"role": "system", "content": "You summarize web pages in short markdown."},
    {"role": "user",   "content": "Summarize this:\n" + website_text},
]

# 3. call the model and read the reply
response = openai.chat.completions.create(
    model="gpt-4.1-nano",
    messages=messages,
)
print(response.choices[0].message.content)
Gotchas that cost beginners an hour: the file must be named exactly .env (not .env.txt) and saved before load_dotenv() can see it; the key must start with sk-proj-; and the notebook kernel must point at your .venv, not a system Python.
