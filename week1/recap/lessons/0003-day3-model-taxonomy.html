LLM Engineering ● Week 1 ● Day 3 Recap

Base, chat & reasoning models

A working taxonomy of LLMs — and the limits frontier models hide behind confidence.

Why this matters for the switch: "which model should we use?" is a question you'll be asked in every AI role and interview. The answer starts with knowing what kind of model you're holding — and trusting none of them blindly.

Today's win

You can explain the difference between a base, a chat/instruct, and a reasoning model — and name when each is the right tool.

The taxonomy

Models differ by how they were trained, and that dictates how you use them.

TypeWhat it isUse it forTradeoff
BaseRaw next-token predictor on bulk text; no instruction tuningA starting point to fine-tune for novel tasksWon't reliably follow instructions; needs prompt tricks
Chat / InstructBase model tuned on system/user/assistant turns via RLHFInteractive use, fast cheap inference, creative textLess deliberate reasoning depth
ReasoningEmits a visible thinking trace before the answerPuzzles, math, multi-step logicSlower & pricier (thinking tokens); can overthink
HybridDecides per query how much to reason (GPT-5, Gemini 2.5 Pro)General-purpose defaultVariable latency

Key concepts

  • RLHF turns a base model into a chat model. Reinforcement Learning from Human Feedback trains the model on good message→response behavior, making it follow instructions.
  • Reasoning models "think" in tokens. They generate intermediate reasoning before the final answer — you pay for those thinking tokens, but they score higher on hard problems.
  • Budget forcing. The S1 paper (Jan 2025) found that injecting the word "wait" into a reasoning trace makes the model reflect deeper — a startlingly simple lever.1
  • Frontier models hallucinate with confidence. They are trained to sound plausible, not to be true. Confidently wrong is the dangerous failure mode.
  • Knowledge cutoffs are real. Each model only knows up to its training date; web search bolted on top patches this but is not part of the model.
  • Supervision is mandatory. Most dangerous for a junior who can't smell a wrong answer — in the course's example, a model invented elaborate code instead of flagging a misnamed model.
  • Agentic AI chains many model calls into autonomous multi-step work: Deep Research, browser Agent Mode, and Claude Code reading a whole codebase to write runnable code.
Interview-ready framing: "Why not always use a reasoning model?" — Because chat models are faster and cheaper, and reasoning models can overthink simple tasks. You match model type to task difficulty, the same way you matched model size on Day 1.
