Prompt chaining, JSON & streaming

Wiring multiple model calls into a real product: the brochure generator.

Why this matters for the switch: this is the first day you build something that looks like a product, not a demo. Chaining calls, forcing structured output, and streaming a response are the exact patterns every LLM app ships with. This is portfolio material.

Today's win

You can chain two model calls — one returning JSON you parse in Python, one streaming text to the screen — into a single working tool.

The brochure generator, end to end

Goal: point at a company's homepage, get back a polished brochure. One ChatGPT prompt can't do it well, so you chain: call 1 picks the relevant links as structured JSON; Python filters and fetches them; call 2 writes the brochure from that content, streamed token-by-token.

Call 1 — get structured links as JSON

response = openai.chat.completions.create(
    model="gpt-5-nano",
    messages=[
        {"role": "system", "content": link_system_prompt},   # shows a JSON example (one-shot)
        {"role": "user",   "content": get_links_user_prompt(url)},
    ],
    response_format={"type": "json_object"},    # force valid JSON at inference
)
links = json.loads(response.choices[0].message.content)   # now it's a Python dict

Call 2 — write the brochure, streamed

stream = openai.chat.completions.create(
    model="gpt-4.1-mini",
    messages=[...],
    stream=True,                       # return chunks as they're generated
)
for chunk in stream:
    piece = chunk.choices[0].delta.content or ""
    print(piece, end="")       # typewriter effect

Key concepts

  • Prompt chaining. Feed one call's output into the next, with Python logic in between. It's how you build specialized products instead of one giant prompt.
  • JSON works because the model was trained on tons of it. Asking for JSON is far more reliable than ad-hoc "use bullet points" instructions — the structure is familiar to the model.
  • One-shot / multi-shot prompting. Put one example of the desired output in the prompt (one-shot); add more for harder formats (multi-shot). Examples beat descriptions.
  • response_format={"type": "json_object"} constrains generation so only tokens forming valid JSON are allowed — guaranteed-parseable output, even though the model doesn't "understand" JSON semantics.
  • Streaming with stream=True yields delta.content chunks (Server-Sent Events) so the user sees output immediately instead of waiting for the whole reply.
  • The business lens. Wrapping model calls in real logic — scraping, filtering, assembling — is what turns a chatbot into a vertical product (recruiting brochure, investor one-pager, …).
Model selection in action: Day 5 uses two different models on purpose — cheap gpt-5-nano for the mechanical link-extraction, balanced gpt-4.1-mini for the quality-sensitive writing. That's the Day 1 cost/quality dial and Day 3 taxonomy applied to one pipeline.
